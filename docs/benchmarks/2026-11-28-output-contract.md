대상은 `lmstudio_20261128-012050_dc96b757`에서 확인된 파일 블록 형식 오류와

## Qwen 파일 블록

기존 Qwen 코드 응답 378개 중 형식 오류가 126개였다. 저장된 응답을 새 정리 정책과
엄격한 파일 파서에 다시 넣었을 때, 끝에 여분의 `</file>`이 붙은 113개를 수용했고
나머지 13개는 계속 거부했다. 이는 **파일 형식을 수용한다는 결과**이며,
이전 실험을 재채점하거나 단위 테스트 통과를 확인했다는 뜻은 아니다.

`documented-tags-v2`는 응답 끝에 독립된 여분 닫는 태그만 남았고 모든 파일 블록의
Python 문자열·태그 경계가 명확할 때만 그 태그를 제거한다. 코드 본문, 경로 보호,
제공 데이터 보호, 전체 변경의 원자적 검증은 유지한다. 문자열 안의 가짜 파일 블록,
파일 사이의 여분 태그, 다른 파일로의 중첩은 복구하지 않는다. 원본 응답과 정리 후
응답, 제거한 원본 줄 번호, 적용 여부를 모두 남긴다.

## gpt-oss 빈 최종 답변

기존 37번 modeling 독립 반복 1(seed 43)의 수정 1회 입력을 별도로 재현했다.
기존과 같은 설정의 일반 응답·스트리밍 응답 모두 `content`가 비었고 `reasoning`은
있었으며 `finish_reason`은 `stop`이었다. `tool_choice=none`도 이 사례를 막지 못했다.

같은 요청의 `lms log stream --json --source model` 원문에서 다음 헤더가 확인됐다.

```text
<|end|><|start|>assistant<|channel|>commentary to=python code<|message|>
```

모델은 최종 파일 블록 대신 제공하지 않은 Python 도구로 코드를 보내려 했다.
이때 호환 API는 `content=""`, `tool_calls=[]`를 반환했다. 따라서 이 재현 사례는
입력 컨텍스트 초과나 클라이언트에서 정상 최종 코드를 버린 경우가 아니다.
관찰하지 않은 과거 모든 빈 응답의 내부 원인이 같다고 단정하지 않는다.

`text-only-final-v1`은 두 LM Studio 모델에 동일한 고정 시스템 지침을 추가한다.
실행 도구가 없음을 구체적으로 명시하고, 추론 후 요청된 형식을 갖춘 최종 답변을
제출하도록 안내한다. 도메인 모델 요청에는 JSON, 코드 요청에는 파일 블록이라는
기존 사용자 메시지의 형식 지침을 따른다. 새로운 도구나 별도 재생성 루프는 없다.
시스템 지침도 컨텍스트 계산에 넣고, 지침 원문·정책을 manifest와 usage에 저장한다.

API가 제공하는 최종 답변과 추론 필드의 글자 수를 `response_diagnostics`에 기록한다.
추론이나 도구 실행용 내용을 최종 코드로 사용하지 않는다. 빈 답변·도구 호출·잘린
응답이 다시 생기면 기존처럼 거부하고 20회 수정 예산 안에서 다음 수정을 요청한다.
이 지침은 모델에게 주는 출력 계약이며 빈 답변을 완전히 막는 강제 문법은 아니다.
