# 채점 전 태그 정리와 결과 무결성

## 현재 실행기: 자동 정리

새 생성·수정 실험은 완결된 코드 응답을 받은 뒤, 파일 적용과 단위 테스트 **전에**
`generate/tag_cleanup.py`의 `documented-tags-v1` 정책을 적용한다. Qwen, gpt-oss,
Claude에 같은 규칙을 사용한다. 추가 모델 요청은 없으며 원래 요청의 수정 횟수·토큰 사용량을 유지한다.

- Python 파일 블록 안에서, 문자열 밖에 있고 내용이 `</parameter>` 또는 `</invoke>`뿐인 줄을 제거한다.
- 닫히지 않은 파일 블록 안에 **같은 경로**의 파일 블록이 독립된 줄에서 다시 열리고
  완결된 내용이 나오면, 마지막 재출력 내용을 사용한다.
- 문자열·비 Python 데이터·인라인 태그·다른 태그는 바꾸지 않는다. 따옴표 경계가
  불분명한 경우도 정리하지 않는다. 서로 다른 경로의 중첩, 이미 닫힌 블록의 중복,
  삭제 명령이 섞인 중첩은 복구하지 않는다.
- 정리한 응답에도 기존 경로·제공 데이터 보호·중복 파일 검증을 적용한다.
  검증에 실패하면 전체 변경을 거부하고 이전 코드와 그 코드의 검증 결과를 유지한다.
  인식하지 못한 형식은 다음 수정 요청에서 모델에 피드백한다.

각 실험의 `rounds/000/`, `rounds/001/` 등에서 확인한다.

| 파일 | 내용 |
|---|---|
| `response.txt` | 모델의 원본 응답, 수정하지 않음 |
| `cleaned_response.txt` | 정리로 달라진 응답만 저장 |
| `tag_cleanup.json` | 정책, 전후 해시, 파일별 제거 태그·원본 줄 번호·재출력 교체 횟수 |
| `tag_cleanup.txt` | 사람이 읽을 수 있는 정리 요약 |
| `record.json` | 실제 적용 상태, 소스 해시, 검증 결과와 회차 |
| `src/` | 해당 회차의 실제 코드 스냅샷 |

`changed=true`는 응답을 정리했다는 뜻이고, `applied=true`는 경로 검증과 파일 반영까지
완료했다는 뜻이다. 테스트 통과 여부는 별도 검증 결과로 확인한다. 잘린 응답이나
프로토콜 오류는 자동 정리를 시도하지 않는다. 최초 원본 `codegen_response.txt`도 보존한다.

`run.json`이 있는 실험은 코드·회차·테스트 입력의 해시로 검증한다. `src/`를 손으로
고치거나 `result.json`만 지워 재채점하지 않는다. 변경한 조건으로는 새 실험을 만든다.

## 기존 단일 생성 결과의 수동 규칙

`prdbench`에서 가져온 기존 규칙은 파일 적용 뒤 사람이 같은 두 태그 줄을 제거하고,
닫지 않은 동일 파일의 재출력 부분을 남긴 뒤 `tag_cleanup.txt`에 기록하는 방식이었다.
현재 자동 정책은 이를 위 범위에서 보수적으로 구현한다.

`run.json`이 **없는** 과거 단일 생성 결과에만 기존 수동 절차를 사용할 수 있다.
먼저 결과를 별도 복사하고 원본 응답을 보존한 뒤, 정리 내역을 기록하고 복사본의
`result.json`을 삭제해 재채점한다. 수정 반복 실험에 이 절차를 적용하지 않는다.

벤치마크 테스트·인터페이스·태그 정리 정책이 달라진 결과는 같은 조건의 결과로 섞지 않는다.
이전 실험을 다시 검증하려면 당시 벤치마크와 실행기를 함께 사용해야 한다.
